# 模块 03 · 组件层（`src/components/`）

> **一句话**：只负责**画**和**转发用户意图**。组件不查数据、不发请求、不维护业务状态
> （唯一的例外是"行内编辑/确认"这类纯 UI 态、以及滚动锚定这类 DOM 态）。
> 所有业务判据都从 store 或 `lib/` 的纯函数来 —— 这是"同一件事只有一个入口"纪律的落点。

| 组件 | 行数 | 一句话 |
| --- | --- | --- |
| `App.vue` | 315 | 布局骨架 + **路由落地（打开会话的唯一入口）** + Settings 抽屉 |
| `Sidebar.vue` | 394 | 会话列表：搜索（客户端过滤）、分组、行内改名、原位二次确认删除、桌面折叠/移动抽屉 |
| `ChatWindow.vue` | 268 | 消息区：按轮分组渲染 + **分波滚动锚定** + 自动翻页 + 错误横幅 + 空态 |
| `MessageItem.vue` | 212 | **一段**消息：用户气泡（含复制）/ 正文段（markdown）/ 工具行段 / 压缩摘要 / 轮级页脚 |
| `InputBox.vue` | 244 | 按**相位分派**的按钮与 Enter；输入历史 ↑↓；自动长高；输入法合成期保护 |
| `RunStatus.vue` | 231 | 四态状态行（灯 + 状态词 + 计时 + 模型/窗口/本轮输入）+ 审批卡片 + 安全闸门说明 |
| `ContextGauge.vue` | 78 | 状态行的后半段：`模型 │ 窗口 │ 本轮输入合计`（自带前导分隔符，无数据整段不渲染） |
| `TurnAvatar.vue` | 26 | 轮首头像（只回答"这是谁说的"，**不挂状态灯**） |
| `Notice.vue` | 45 | 自动消失的轻提示（5s / 点击即消），目前只用于"地址里的会话不存在" |

## 1. `App.vue` —— 打开会话的唯一入口

```ts
onMounted():
  checkHealth(); loadSessions()
  watchForeground(() => resumeSync())          // 只订阅"回到前台"，不做任何保活
  const initial = currentRoute(); markInitialRoute(initial)
  offRoute = onRouteChange(r => applyRoute(r))
  applyRoute(initial)                          // 刷新恢复会话靠这一步
  resumeSync()                                 // 欢迎页也要对一次账（页面可能被回收过）
```

`applyRoute()` 的四种结局（**这是评审"地址即状态"时唯一要看的地方**）：

| 地址 | 结果 |
| --- | --- |
| 裸域名 | `goHome()`（欢迎页，不预建空会话） |
| `#/s/<id>` 且就是当前会话 | 直接返回 |
| `#/s/<id>` 不存在（被删/归档/乱写） | `navigate(null, {replace})` + 轻提示「该会话不存在，请重新创建」（5s 自动消失、点击即消） |
| 生成中试图切会话 | 把地址**撤回**当前会话（否则"地址 B、画面 A"） |

侧栏点击 → `navigate(id, {push})`（返回键能回上一个会话）；程序自己纠正地址 → `replace`。

Settings 抽屉是**刻意最小化**的：连接状态（含 `前端构建 {{ buildId }}`）、外观切换、头像、
快捷键说明、关于。**不做模型切换 / Prompt / Agent 配置**。

## 2. `Sidebar.vue`

- **搜索是客户端过滤**（`displayTitle + preview + id` 三处匹配）：上游没有搜索端点，
  所以必须靠 `loadSessions(200)` 取满上限。
- **行内操作**（无原生 `confirm`/`prompt`）：改名 = 原位变输入框（Enter 保存 / Esc 取消，重名或超 100 字
  行内红字）；删除 = 原位二次确认且**文案带标题**。**只提供单行删除**，没有任何批量入口。
- **点外面自动收起**用 **document 捕获阶段的 `click`**，不是 `blur`：
  `blur` 会抢在按钮 `click` 之前触发 ⇒ 编辑态被关掉、保存静默失效。捕获阶段先于目标自身处理执行，
  所以"点在行内不取消、点在行外先取消再走原逻辑"天然成立。
- 正在跑的那一轮所属会话**禁止改名/删除**（服务端 turn 还在写它）。
- 列表行容器是 `<div class="group flex">` 而**不是** `<button>`：否则行内按钮会串味
  （点重命名等于点开会话）+ 非法 HTML。

## 3. `ChatWindow.vue` —— 滚动锚定（本项目最"物理"的一段）

- **按轮分组**：`groupIntoTurns(store.messages)`（纯函数，见 `lib/turns.ts`）→ 轮内 `space-y-2`、
  轮间 `mt-6`。不这样分，"同一轮内的先后"和"新一轮的提问"看起来一样远。
- **自动翻页**：`scrollTop <= 60px` 触发（不是 `== 0`，否则先露一段空档）；加载后自己补偿
  `scrollTop`（prepend 会让 `scrollHeight` 变大）；重入由 `loadEarlier()` 自己兜底。
  **"加载更早"按钮不能因为有了自动加载就删**：内容不足一屏时容器根本不产生滚动事件。
- **分波滚动锚定**（修一个"打开会话停在半路 21%~50%"的 bug）四件事，缺一处就白干：
  1. `watch(tail)`（消息条数 + 末条长度）—— 覆盖"主动追加"的情况；
  2. `ResizeObserver` 盯**内容容器**（`.mx-auto.max-w-chat`，必须含"加载更早"行）—— 因为工具行/表格
     这些"不改 tail 的长高"不会触发 ①；**不能只盯 scroller**（flex 里它自己盒子固定，一个通知都收不到）；
  3. 内容容器是"有消息才渲染"的 ⇒ `watch(ref)` 在它出现时补 `observe`；
  4. 打开会话给一个**锚定窗口** `followUntilSettled()`（每帧贴底，直到高度连续两帧不变、1.5s 兜底）——
     "只贴一次"永远可能早于最后一波长高。
- `tail` 是一个**魔法启发式**：`messages.length * 10000 + 末条 content.length`（见 `文档/04` B 级观察）。
- 错误横幅在这里（`store.bootError`）：创建会话/拉列表失败必须可见，否则"点发送没反应"。

## 4. `MessageItem.vue`

- 四种渲染形态：用户气泡（`whitespace-pre-wrap`，**不解析 markdown**）/ 正文段（markdown + 高亮 +
  代码块复制按钮 + 流式光标）/ 工具行段（`<ol>`，常驻小字行，`● ✓ ✗ 名称 "预览" (耗时)`）/
  压缩摘要（`<details>` 折叠）。
- **轮级页脚挂在本轮最后一个段上**（统计 /「· 已中断」/ 错误），所以两种段共用同一份页脚渲染。
- **流式性能**：内容变化 → `requestAnimationFrame` 节流 → `renderMarkdown(整段)` 整段重渲染
  （不做增量 diff）；装饰（复制按钮、光标）在 `nextTick` 里用原生 DOM 做（`v-html` 出来的节点拿不到 Vue 作用域）。
- 用户消息的复制按钮是**常驻可见**的（手机没有 hover）；无剪贴板 API 时如实说"复制失败"，不假装成功。
- ⚠️ 已知缺口：正文里的**链接点击没有被拦截**（点一下整页跳走，SPA 卸载）—— 见 `文档/04` A4。

## 5. `InputBox.vue` —— 相位分派（交互口径最集中的地方）

| 相位 | 按钮 | 点它 / Enter |
| --- | --- | --- |
| 思考 / 调工具 / 等审批 / 后台在跑 | 「发送」（+ 次要「暂停」） | **补充信息**（steer） |
| 正在输出正文（`writing`） | 「暂停」 | 中断；Enter **静默不提交** |
| 没在跑 | 「发送」 | 开新的一轮 |

- `busy = store.streaming || phase === 'background'` —— **两种"忙"都要给暂停**（不变式：用户在任何状态下
  都能取消这一轮）。
- Enter 发送 / Shift+Enter 换行 / **中文输入法合成期绝不发送**（`composing || e.isComposing`）。
- `↑`/`↓` 翻最近 20 条输入：合成期让路、多行草稿光标不在首行时让路（那时是在文本里移光标）。
- 布局是**上下两段**（文字区 `w-full` 占满整宽，按钮单独一行）：早期 textarea 与按钮并排会让
  文字到按钮左缘就断行、输入长内容时按钮上方一片空。
- ⚠️ 已知缺口：`mode === 'steer'` 且 `steer()` 静默返回时，输入框已清空而话没送出去 —— 见 `文档/04` A3。

## 6. `RunStatus.vue` + `ContextGauge.vue` —— 状态行（v2.16 定型）

```
🟢 时刻准备着 │ qwen3.8-flash │ 窗口 1m │ 本轮输入合计 21.8k
🟡 忙碌中 12.4s     （灯在动：静态黄灯跟"卡住了"长得一样）
🟠 等待审批 / 已中断
🔴 失败（请重试）    （只有"服务端根本没收到"才给「重试」按钮）
```

- **判据全在 `lib/turnStatus.ts`**（纯函数、逐条单测），组件只负责画；灯是**派生量**，不缓存不落盘。
- 这一行**常驻**（空闲时是 🟢 时刻准备着），且灯与模型信息**同一行**（`ContextGauge` 是它的子组件、
  自带前导 `│`，无数据时整段不渲染 ⇒ 不留孤零零的分隔符）。
- 计时由 200ms `setInterval` 驱动的 `tick` 刷新，用 `performance.now()` 差值。
- 审批卡片：工具名 + 被标红的命令原文 + 由**服务端给的 `choices`** 动态渲染的四个按钮
  （批准一次 / 本会话都允许 / 永久允许 / 拒绝）；回话后显示"已回话：…，等服务端继续…"。
- 安全闸门说明块（`store.run.blocked`）：文案按通道分（审批超时/被拒 vs 硬规则），见 `lib/security.ts`。
- 刻意**不列工具**（工具行在对话流里）：同一件事不要在"状态行"和别处都说 —— 曾经轮首也挂灯，
  与状态行 100% 重叠、历史轮清一色绿点没有信息量，被撤掉。

## 7. 组件层的三条纪律

1. **禁止 `fetch`**（唯一数据入口是 store 的 action）；
2. **不做业务判据**：判据抽到 `lib/` 纯函数，"什么时候才变红"这类逻辑必须能被单测逐条锁住；
3. **同一条信息只在一个地方显示**：状态/工具/构建标识都有唯一归属，别为了"顺手"在多处重复。
