# 模块 06 · 测试与验证层

> **一句话**：三层阶梯，各管一段，**不混用** —— 单测管判据、真链路 e2e 管上游契约、
> 真浏览器探针管布局与真实时序。三层都踩过"假绿/假失败"，所以下面一半篇幅是纪律而不是清单。

## 1. 三层阶梯

| 层 | 命令 | 管什么 | 成本 | 现状 |
| --- | --- | --- | --- | --- |
| ① 单测（jsdom） | `node node_modules/vitest/vitest.mjs run` | 判据、分段规则、分页去重、SSE 切片、审批状态机、路由、组件行为 | 秒级 | **28 文件 / 319 用例，实测全绿（2026-09-18）** |
| ② 真链路 e2e | `set -a; . /opt/data/.env; set +a; npm run e2e` | 只有打真 API 才能发现的契约问题（帧形态、终态语义） | 数十秒 + 烧 token | 3 个 spec，**抓到过 2 个真 bug** |
| ③ 真浏览器探针 | 自建探针脚本（真内核 + 本地 dist + 自建反代 / 或直打线上） | jsdom 抓不到的一切：布局、宽度溢出、滚动锚定、地址即状态六条、线上版本指纹 | 分钟级 | 在维护者工作区与技能库里，**不在本仓库**（见 §5） |

| 其它（3） | `style.spec`（CSS 宽度契约）、`test-environment.spec`（测试环境自身）、`src/App.spec` | 环境与契约回归 |

**测试环境的两个坑（都已修，但每次新写用例都要注意）**：

1. **`localStorage` 在 vitest 里是 `undefined`**：裸 jsdom 明明有，但 Node 22+ 的内置实验性实现
   （无 `--localstorage-file` 时取值为 `undefined`）会**遮蔽** jsdom 那份 ⇒ 症状是
   `Cannot read properties of undefined (reading 'clear')`。修法：`src/test-setup.ts` 装一个
   **语义完整的内存 `Storage`**（别用"记录调用次数"的 mock 糊过去，那样测的不是真逻辑），
   并给 jsdom 一个真实 `url`（不透明 origin 下 jsdom 根本不建 localStorage）。
2. **`store` 是模块级单例**：断言"启动态/空态"的用例必须在 `beforeEach` 里显式清
   `currentId/messages/sessions/run`，否则 RED 阶段会**假通过**（还原源文件后照样绿）。

## 3. 真链路 e2e（`e2e/`，独立配置）

```ts
// e2e/vitest.config.ts 的三点差别（都是为了"打真 API、跑得久"）
include: ['e2e/**/*.e2e.spec.ts']   // 与 npm test 互不干扰
testTimeout: 300000                 // 一轮真模型对话几十秒起步
root: fileURLToPath(new URL('..', import.meta.url))   // ⚠️ 必须绝对路径（相对路径按 CWD 解析，实测指错）
```

| spec | 覆盖 |
| --- | --- |
| `real-runs.e2e.spec.ts` | 普通轮 / 工具轮 / 中断 / 历史回归 / 清理（**只用自建探针会话，跑完自删并复查 404**） |
| `background-resume.e2e.spec.ts` | 掐断事件流 → 回前台 → 正文与服务端状态被同步回来（**断流不取消任务**） |
| `tools-inline.e2e.spec.ts` | 真数据冒烟：真实会话 → `normalize` 的工具段配对率/预览率/耗时率 |

**四条纪律**：

1. **先钉模型**（`POST /api/sessions/{id}/model`，如 `xyy/deepseek-flash`）：不钉就走网关默认模型，
   实测它会把"只回复两个字"执行成一整套复盘 —— 既贵又不稳定。
2. **断言只赌结构不赌措辞**（"正文非空 + 有 `run_id` + 有统计"），否则模型随口改文案用例就红。
3. **它抓的是单测抓不到的东西**：已抓到 ① `/v1/runs` 的 SSE 帧没有 `event:` 行（照旧通道写法解析会把
   所有事件当未知事件忽略）；② 收到 `run.cancelled` 被判成"完成"。
4. **不放进 `npm test`**（一轮几十秒还烧 token）——单测与真链路各有自己的配置与入口。

## 4. 真浏览器探针：为什么必须存在

jsdom **不做布局**（`scrollWidth` 恒 0、`ResizeObserver` 不存在、`MutationObserver` 时序不可信），
所以下面这类 bug 只能靠真内核 + 真时序抓：

- 打开长会话停在半路（贴底贴早了、之后没人跟）；
- 手机端 10 列表格把整个消息区撑宽、能左右拖；
- 地址即状态六条（刷新落原会话 / 切 B 后刷新落 B / 返回键 / 无效 id 提示三态 / "新对话"不建空会话 /
  跑着时切会话地址撤回）；
- 上线后"到底发的哪一版"。

探针的形态：本地 `dist` + 自建 node 反代（注入 key、**删掉 `Origin`/`Referer`**）+ 真 API + 真模型 +
`chrome-headless-shell`（`executablePath` 直连）。

**探针自身的坑（比被测代码更容易出问题）**：

| 坑 | 症状 | 修法 |
| --- | --- | --- |
| 忘了 `await server.listen(...)` | `ERR_CONNECTION_REFUSED`，看着像前端崩了 | 先查探针自己 |
| 代理没删 `Origin`/`Referer` | 整页从第一帧就是 403 错误态，后面所有断言跑在"假现场"上 | `delete headers.origin; delete headers.referer` |
| `page.evaluate(fn)` 的函数不自包含 | `ReferenceError: xxx is not defined`（函数被序列化后送进页面，闭包不存在） | 逻辑整段写进 `evaluate` 内部，外部值当第二个参数传 |
| `check()` 参数顺序写反 | **所有断言都过**（第一个位置收了非空字符串，恒真） | 签名设计成写错就报错；新脚本先做一次**反向自检**（故意让一条断言必失败） |
| 写死 `chrome-headless-shell` 路径 | playwright 升级改目录名就报"浏览器不存在" | 自动发现：`readdirSync('/opt/hermes/.playwright')` 取最后一个匹配目录 |
| 用 `.group` 断言**用户**气泡 | 恒 false（`.group` 只在助手分支上） | 用 `innerText` 包含判断 |
| 探针按空格切分取工具名 | 取到的是标记圆点 ⇒ 工具名恒空 | 先剥标记再切：`t.replace(/^[●✓✗]\s*/, '')` |
| Vue 压缩元素间空白 | 断言"这行只有 A 和 B"按空格写会假失败 | 按内容比或用 `toContain` |
| 用会重构的容器当"锚" | prepend 后 `.md-body` 首句已变，量出上万像素的假偏移 | 用**叶子元素的文本指纹**定位同一个点，并校验前后命中数都是 1 |

## 5. 探针不在仓库里（认知负担，也是改进点）

真浏览器探针目前放在维护者的工作区（`/opt/data/.verify/**`）与技能库里，仓库里**只有 `e2e/`**。
好处：不污染仓库、可以随便改；坏处：**换个人接手就把这套能力丢了**。
建议（见 `文档/04` D 级）：至少把"地址即状态六条"与"线上版本指纹"两个脚本收进仓库
（它们最稳定、复用价值最高），其余留在工作区。

## 6. 验证纪律（这一节的每一条都对应一次踩坑）

1. **新断言必须 RED/GREEN**：`git stash push -q -- src/ && vitest run && git stash pop -q` ——
   还原实现后新断言必须**全红**，否则它锁的不是你以为的东西。
2. **旧断言按新口径改写，不要一删了之**：它们是回归网（删了等于把过去踩过的坑重新开放）。
3. **凡"事件驱动的修复"，必须有一条断言锁住"事件源接上了"**：滚动锚定的第一版修复单测全绿、
   真浏览器无效 —— 因为测试里手动调用了 `ResizeObserver` 回调，而应用代码**根本没 observe 对元素**。
   修法：给假 RO 记录 `observe()` 到的元素并断言。
4. **假失败先怀疑断言，真差异先修代码**：探针报"水位与灯 `top` 不等（774 vs 776）"，第一反应是
   "探针太严" —— 一查是真差异（`text-[11px]/leading-5` 与 `text-xs` 盒高不同）⇒ 修实现统一 `leading-4`，
   而不是把断言放宽到 4px 了事。分界线是"去查清那个数字是怎么来的"。
5. **对照/归因要 A/B**：同一探针跑两次产物（`DIST_DIR=<main 产物>|dist`），两边行为一致 ⇒
   不是本次引入的回归；差异只有在**修复前必现、修复后为 0** 时才闭环。
6. **数字对不上先看 `git log`**：这个 clone 是多会话共用的（`git status` 干净**不等于**没人在动工作区，
   对方可能已经提交）—— 别急着给异常编"工具抽风"的解释。
