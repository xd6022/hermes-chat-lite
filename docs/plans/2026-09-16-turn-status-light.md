# 输入框上方状态行（Claude 式）+ 每轮一个状态戳 —— 计划书 + 状态看板

- **立档**：2026-09-16 CST（Asia/Shanghai）
- **分支**：`feat/turn-status-light`（从 `origin/main` 的 `aeb8094` 开；v2.13 已合入 main）
- **起因**：用户要把交互做成"两个人交谈"的样子，并要一个**状态指示**。
  参照物是他用 Claude 时的体验 —— 图标会闪、旁边有状态词（`Ready` / `baking`），
  **一眼就知道"我是不是还得再等会儿"** ⇒ 这是个**决策信号**，不是装饰。
- **用户拍板（2026-09-16）**：
  ① 接口挂了/中途断了 → 🔴｜② 状态行**带计时**｜③ **颜色 + 状态词并存**｜④ 灯按本文件 §一 口径｜
  ⑤ 审批卡片等**留在原地不搬**｜⑥ 轮首戳滚出视口的代价**接受**｜⑦ **每个助手轮开头都有头像**｜
  ⑧ 头像放配置、默认 `-_-`、Settings 可改（B 方案）｜⑨ 灯**实时计算、不加缓存**｜
  ⑩ 完成的轮**只留绿点**｜⑪ 🔴 处**加「重试」**｜⑫ 侧栏"会话正在跑"黄点**先不做**｜
  ⑬ 老会话历史轮一律 🟢｜⑭ **状态词用中文**｜⑮ 工具行**合并成一个标记 + 颜色**（"很棒"）｜
  ⑯ 审批时状态行走 **A 方案**（`🟡 等待你批准 · {secs}s`，**不带工具名**）｜
  ⑰ **审批卡片本身不处理**（出现概率低，先不管它压缩消息区那事）
- **关键纠偏（走错过一回，记下来）**：中途有一版把状态挪进对话流（轮首），代价是长轮次会滚出视口 ——
  而那恰好是最需要"要不要等"的场景。**结论：问题不在"位置"，在"内容"** ——
  输入框上方原本挂的是装饰提示词 + 重复的工具名（那确实是噪音），但那个**位置**是对的
  （位置固定才能回答"要不要等"）。最终方案 = **位置不动，内容升级**。

## 一、口径（已拍板，实现时照这张表，别再问）

### 1.1 输入框上方状态行 —— 同一位置依次变

`🟡 思考中 3.2s` → `🔵 mysql.query 12.4s` → `🟡 输出中 12.0s` → `🟢 已完成`（停留 ~3 秒后收起）
⇒ 落到 `RunStatus.vue` 现有位置（`<RunStatus />` 在 `<ContextGauge />` 之前），**位置不动**。

| 相位 | 灯 | 状态词 |
| --- | --- | --- |
| `thinking` | 🟡 | `思考中 {secs}s` |
| `tool` | 🔵 | `{工具名} {secs}s`（工具名**不翻译**，它是标识符） |
| `writing` | 🟡 | `输出中 {secs}s` |
| `approval` | 🟡 | `等待你批准 · {secs}s`（**不带工具名** —— 卡片标题已经写了同一个名字，重复；计时继续走，这一轮没结束） |
| `background` | 🔵 | `连接已断开，任务仍在后台执行` |
| `syncing` | 🔵 | `正在同步…` |
| `done` | 🟢 | `已完成`（停留 ~3s 后收起） |
| `aborted` | ⚪ | `已中断这一轮`（停留 ~3s 后收起） |
| `error` | 🔴 | `出错：{message}` + **「重试」**（常驻到下一轮） |

**颜色语义与全站一致**：🔵＝进行中（`background` 相位本来就是天蓝"蓝色=进行中，不是错误也不是中断"）；
🟡＝思考/等待；🟢＝完成；🔴＝错误。

**留在这里、不搬走的**：🔐 审批卡片、⛔ 闸门拦截说明、断连提示、轮末对账提示
（它们本来就属于"当前这一轮"）。⇒ **不搬卡片**是这套方案省下的最大一块工作量。

### 1.2 轮首戳（对话流里，永久痕迹）

每轮开头 `{头像} {灯}`：跑着 `-_- 🟡`｜完成 `-_- 🟢`｜出错 `-_- 🔴`｜中断 `-_- ⚪`。
**固定占一行高**（跑着时那一行就在，跑完只换颜色）⇒ 零高度变化。
**不放重试按钮**（重试只在上面那条，避免两处按钮）。

### 1.3 工具行标记（`MessageItem.vue`）

一个标记 + 颜色：**`●` 蓝＝在跑｜`✓` 绿＝成功｜`✗` 红＝失败**。
不只用颜色（`🔵🟢🔴` 形状一样，色盲看不出、截图也糊）—— 保留形状差异＝双通道。

### 1.4 判据（不因改版而变）

- 起步亮灯：`POST /v1/runs` 返回 202（"能调到 hermes 且没立即报错"）
- **绿：只有收到 `run.completed`**（不能用"没动静了"猜 —— 坑 19）
- 红：服务端明确发 `error`，或后端**确实**不可用
- **"连接断了但服务端还在跑"绝不变红**（🔵）—— 切后台/锁屏/换网是常态，报错会让人以为长任务白费（9/13 真机纠偏过）
- 刷新那一瞬（`store.run` 归零 + 重连未回 ≈1s）→ `🔵 正在同步…`，**不闪绿**
- **灯是实时计算的派生量**：不加缓存、不落盘

## 二、代价（已接受，交付说明里要写明）

1. 轮首戳在长轮次会滚出视口（主需求由位置固定的状态行覆盖）
2. 换设备 / 清浏览器数据 / 超 6 小时 ⇒ 认不出在跑的那一轮
3. 重开老会话：历史轮一律 🟢（服务端**不记录"哪一轮被中断过"**，`end_reason` 只在会话级）

## 三、有意开的口子（用户已知悉）

正在跑的工具名出现在两处：上面状态行 `🔵 mysql.query`（**瞬时状态**）与对话流 `● mysql.query "…"`（**永久记录**）。
与"装饰提示词 + 重复工具名"不同：前者是同一份信息摊两遍，这里是两个不同职责。

## 四、坑位预判（实现时留神）

1. **状态行高度**：状态词长度会变（`思考中 3.2s` 与 `连接已断开，任务仍在后台执行` 差很多）⇒
   固定一行高 + 文字截断，否则长文本会把水位行/输入框顶下去，且触发贴底抖动。
2. **轮首戳零高度变化**：跑着时就把那一行画出来（只换颜色），别"跑完才插节点"。
3. **`RunStatus.spec.ts` 现有断言**：`已中断这一轮` 等旧断言按新口径改写，**不要一删了之**（它们是回归网）。
4. **`store.run.currentTool`**：v2.13 后状态行只用它做 tooltip；本次要重新用它显示工具名 ⇒ 确认它被正确复位（轮末清空）。
5. **「重试」的语义要收窄（重要）**：只有"**这一轮根本没成功发出去**"（`POST /v1/runs` 就失败／后端确实不可用）才给「重试」——
   这时服务端没收到，重发是安全的。若是"发出去了但中途断了"，**不给重试**（给 `已中断`／🔵 后台执行中）——
   因为服务端可能已经落库，重发会出现两条输入。
6. **现有断言按新口径改写，别一删了之**：`RunStatus.spec.ts` 里有一条写死了 `等待你批准：terminal`（等审批用例）——
   改成"不带工具名"的新口径（`等待你批准 · {secs}s`）。它是回归网，删掉等于丢掉一个坑。

## 五、实现锚点（已勘察本机代码，只读未改；开工时照这些落点写）

### 5.1 红灯与「重试」的判据（**现在有硬依据了**）

`send()`（`stores/chat.ts:1538`）只有两条"失败"路径：

| 失败路径 | 现场表现 | 灯 | 给重试吗 |
| --- | --- | --- | --- |
| ① 建会话就失败（常见：反代没注入 key → 401） | `store.bootError = '无法创建会话'`，这一轮**根本没起** | 🔴 | **给** |
| ② `POST /v1/runs` 或流的传输层异常 | `catch` 里 `store.run.phase='error'`、`errorMessage=msgOf(e)`、`ctx.transportError=true` | 🔴 | **看 `runId`** |
| ③ 服务端明确发 `error` 事件 | 走事件归约，`ctx.sawError` | 🔴 | **不给**（服务端收到了） |

**判据（实现就这么写）**：
```
runId === null  ⇒ 服务端根本没收到这一轮 ⇒ 给「重试」
runId !== null  ⇒ 收到了（可能已落库）⇒ 不给重试，只报错
```
依据：`store.run.runId` 只在 `POST /v1/runs` 拿回 `run_id` 后写入（`chat.ts:1070-1071`），
每轮开始由 `resetRun()` 清成 `null`（`chat.ts:1519`），恢复链从 `hcl.activeRun` 记录写回（`chat.ts:1315`）。

### 5.2 灯与计时的起点

`resetRun()`（`chat.ts`）一轮开始时：`phase='thinking'`、`startedAt=performance.now()`、`runId=null`、`currentTool=null`。
⇒ **状态行"亮黄"的起点就是这里**（等价于用户口径"能调到 hermes 且没立即报错"）。

### 5.3 需要"在动"的相位集合（已有常量，别另起一套）

`RunStatus.vue:37` 的 `active` computed：`thinking / tool / approval / writing / background`（+ `store.streaming`）
⇒ 这些相位显示脉冲点并继续计时；`done / aborted / error` 不脉冲。

## 六、本次**明确不处理**的（用户 2026-09-16 定，别顺手做）

1. **审批卡片压缩消息区**：卡片在固定区，变高会挤矮消息区（手机上命令原文长能占小半屏）。
   用户判断"出现概率低"⇒ **先不管**，也不把卡片搬进对话流（那会牵扯滚动锚定）。
2. **侧栏"某会话正在跑"小黄点**：不做。
3. **轮首戳滚出视口**：接受，不加"回到底部"浮动提示。
4. **跨设备 / 清缓存 / 超 6 小时的恢复**：不做（灯是实时派生量）。
