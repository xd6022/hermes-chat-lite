# 模块 05 · 构建与部署层

> **一句话**：这一层存在的唯一理由，是把三件"漏了就静默坏掉"的事**做成会响的错**：
> ① 密钥不进浏览器产物；② SSE 不被任何一环缓冲；③ 缓存分层正确（新 HTML + 长缓存 hash 资源）。
> 附加产出：**"线上到底跑的是哪一版"必须可核验**。

| 文件 | 行数 | 职责 |
| --- | --- | --- |
| `vite.config.ts` | 126 | dev 反代（注入 key、剥 Origin）、构建标识注入、构建与测试配置 |
| `index.html` | ~48 | 主题首帧内联脚本（防深色闪白）、图标三件套、挂载点 |
| `tailwind.config.js` / `postcss.config.js` | 小 | `darkMode: 'class'` + 内容扫描路径 |
| `nginx.conf` | 117 | 静态站 + `/api` `/v1` 反代（注入 Bearer、剥 Origin、SSE 三件套）+ `/api/model-info` 单独转发 |
| `Dockerfile` | 46 | 多阶段构建（node:22-alpine 构建 → nginx:alpine 运行）+ **构建期产物自检** |
| `docker-compose.yml` | 29 | 单服务、`expose: 80`、共用外部网络 `net_openclaw`、**带鉴权的 healthcheck** |
| `.env.example` | — | 只有一个变量 `HERMES_API_SERVER_KEY`（**别照抄占位符**，照抄 = 全部 401） |

## 1. 密钥与跨域（dev 与 prod 各一份，语义一致）

```ts
// vite.config.ts：dev
const upstream: ProxyOptions = {
  target: 'http://127.0.0.1:8642',
  changeOrigin: true,
  headers: { Authorization: *** API_KEY>`, 'Accept-Encoding': 'identity' },
  configure: (proxy) => proxy.on('proxyReq', (r) => r.removeHeader('origin')),   // ★ 必须剥 Origin
}
```

```nginx
# nginx.conf：prod
location ~ ^/(api|v1)(/|$)|^/health$ {
    proxy_pass http://hermes_api;                      # hermes:8642, keepalive 16
    proxy_set_header Authorization "Bearer ${HERMES_API_SERVER_KEY}";   # ★ key 只在这里
    proxy_set_header Origin "";                        # ★ 剥 Origin（否则 403 空响应）
    proxy_buffering off;  proxy_cache off;  gzip off;  # ★ SSE 三件套
    proxy_read_timeout 3600s;  proxy_send_timeout 3600s;                 # agent 单轮可能很久
}
```

**为什么必须在代理层注入**：`API_SERVER_KEY` 一旦进前端代码或 `.env.local`，就会被编译进产物、F12 可见。
代价是反代配置成了功能正确性的前提（`Origin` 那一条尤其隐蔽：**curl 不发送 Origin，所以命令行怎么测都通，
只有真机浏览器会炸**）。

## 2. `nginx.conf` 的四个"加固点"（每一处都对应一次真实故障）

| 加固 | 位置 | 不做会怎样 |
| --- | --- | --- |
| 静态资源缺文件**真 404** | `location ~* ^/[^/]+\.(ico\|png\|…)$ { try_files $uri =404 }` | SPA 回落会把缺文件变成 `200 + 入口 HTML` ⇒ Dockerfile 漏 `COPY public/` 这种错"看着像缓存问题"，静默查不出来 |
| 入口 HTML **一律不缓存** | `location = /index.html { Cache-Control: no-store… ; etag off; if_modified_since off }` | 浏览器按 `Last-Modified` 启发式缓存（国产 webview 更激进）⇒ 手机上"刷了好几次还是老版本" |
| 带 hash 的资源**一年 immutable** | `location /assets/ { max-age=604800, immutable }` | —（前提是入口 HTML 每次都是新的，否则链子断在第一环） |
| `/api/model-info` **单独转发到 dashboard** | `location = /api/model-info { proxy_pass http://hermes_dashboard/api/model/info }` | 并进 `/api` 那条会打到 8642 变 404（这个接口在容器 **9119** 上，不在 API server 上） |

两个易错的技术细节：

- **正则 location 锚在根层**（`^/[^/]+\.…`）是有意的：不锚的话 `/assets/x.svg` 会被它抢走，
  从而**绕过 `/assets/` 那条一年缓存头**（缓存行为悄悄退化）。
- **不要手工 `envsubst < nginx.conf`**：它只应在官方镜像入口脚本里跑（只替换**环境里存在**的名字）。

## 3. `Dockerfile`：构建期就把错炸出来

```dockerfile
COPY package.json package-lock.json ./  &&  RUN npm ci --registry=$NPM_REGISTRY
COPY index.html vite.config.ts tsconfig.json tailwind.config.js postcss.config.js ./
COPY src ./src
COPY public ./public                    # ⚠️ 漏了它：产物里没有 favicon.*，而 nginx 回落会让这些请求 200
RUN npm run build                       # 内含 vue-tsc 类型检查：类型不过就不出镜像
RUN test -f dist/index.html && test -f dist/favicon.svg \
 && test -f dist/favicon.ico && test -f dist/apple-touch-icon.png && test -d dist/assets   # ★ 构建期自检
```

**"把静默的错变成响亮的错"** 的样板：漏拷 `public/` 的后果是"图标改了没生效"，
在浏览器和 curl 里都是 200 —— 很难查。构建期 `test -f` 一炸，问题瞬间定位。
代价：改 `public/` 内容要同步改这份自检清单。

## 4. `docker-compose.yml`：healthcheck 必须打**需要鉴权**的端点

```yaml
healthcheck:
  # /health 不带 key 也返回 200（实测）⇒ 密钥填错照样 healthy，验不出问题
  test: ["CMD-SHELL", "wget -qO- 'http://127.0.0.1/api/sessions?limit=1' >/dev/null 2>&1 || exit 1"]
expose: ["80"]          # 不映射宿主机端口，对外由 Caddy 反代
networks: [net_openclaw] # external，与 hermes 容器同网络
```

`unhealthy` 的语义因此很干净：**反代或密钥有问题**（而不是"页面能开但侧栏空"这种要靠猜的状态）。

## 5. 构建标识与"判版本"（发布纪律的落地）

```ts
// vite.config.ts
__BUILD_ID__ = "461d034 · 2026-09-13 19:55"   // 有 .git 时；镜像里只有时刻
__BUILD_SHORT__ = "461d034"
```

- 取值顺序：`BUILD_ID` 环境变量（给 CI/部署流程留的口子）→ `git rev-parse --short HEAD` + 北京时间
  → 没有 `.git` 就只有时刻。**构建标识自动生成，不手工维护。**
- 显示位置：**只在 Settings → 连接状态**（顶栏与空态那两份都已撤：首屏不摆构建信息）。

**判"线上到底是哪一版"的正确姿势**（不信缓存、不要口令）：

```bash
# ① 入口引用的是哪个 bundle（哈希变了就是新产物）；口令闸门让任何路径都 401，所以走容器内网直问
# ② 抓那个 bundle，按"每个版本独有的文案"grep -c 判版本
#    v2.12 `该会话不存在，请重新创建` 应为 1
#    v2.15 `时刻准备着` = 2、`空闲中` = 0
#    v2.16 `上次已知` = 1（只剩 tooltip）、`前端构建` = 1（只剩 Settings）、`ctx-stale` = 0
```

⚠️ **401 只说明 Caddy 口令闸门在工作**：`basic_auth` 排在 `reverse_proxy` 之前，任何路径
（含不存在的）无口令都是 401 —— 既不代表"没发布"，也不代表"上游挂了"。

## 6. 部署流程（用户在宿主机执行）

```bash
cd <部署目录>/hermes-chat-lite
# 1) 取 key（从 hermes 部署目录的 .env）并写 .env（两个变量名都兼容，取值后 trim 引号）
# 2) 自检：长度必须是 64（不是 64 就说明取错了）
awk -F= '/^HERMES_API_SERVER_KEY=/{print length($2)}' .env
# 3) 起容器 + 看健康
docker compose up -d --build && docker compose ps && docker compose logs --tail=30 chatlite
```

```caddyfile
chat.<域名> {
    basic_auth { <用户名> <bcrypt 哈希> }     # ★ 唯一的安全边界
    reverse_proxy chatlite:80 { flush_interval -1 }   # ★ SSE 不缓冲
}
```

**发布 ≠ 合并**：合并到 main 只说明代码进了仓库；"线上是哪一版"必须用上面的指纹核验，
不能凭"我推了"或"容器重启了"下结论。

## 7. 这一层的两个已知约束（环境限制，不是代码问题）

1. **本机容器没有 docker daemon** ⇒ 镜像/容器只能在宿主机验证；开发侧最高到
   `vue-tsc + vitest + vite build`，加"本地 dist + 自建反代 + 真 API"的真浏览器探针（见 `06-测试与验证层.md`）。
2. **`./node_modules/.bin/<x>` 在这个环境里会被终端拦截**（误判为重启网关），一律
   `node node_modules/<pkg>/bin/<x>.js`；npm 走腾讯云 registry，npm 11 需要 `approve-scripts esbuild`
   否则 vite 起不来。
