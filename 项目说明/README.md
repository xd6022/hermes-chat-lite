# hermes-chat-lite 项目说明

> **这是什么**：一个自用的 Hermes Web 聊天前端（纯前端 SPA，**没有自己的后端**）。它把 Hermes 当"agent 运行时"，
> 自己只负责"看得见、点得动"：会话列表 / 历史消息 / 流式渲染 / 工具执行可见 / 中断 / 审批 / 断线恢复。
>
> **为什么值得读**：它把一个**长跑型 agent** 的客户端该处理的问题几乎全踩了一遍 ——
> 提交与订阅分离、事件流不等同于真相、完成态显式判定、中断 ≠ 断连接、人在环审批（HITL）、
> 轮中插话（steering）、token/缓存观测、上下文压缩边界、页面被回收后的恢复。
> 这些是"接 agent"的通用问题，与它用不用 Vue 无关。

## 三条阅读纪律

1. **这套文档只写"现状 + 方法 + 坑"**，不写变更流水。想知道"某次为什么改"→ 读仓库里的
   `docs/detailed-design.md`（§0 状态看板、§12 已知坑 1–72）、`docs/plans/`、`docs/incident-*.md`。
2. **凡是标了"实测 / 证据"的结论都在代码或文档里有出处**（函数名 + 行号，或仓库内文档章节）。
   本套文档里的行号以基线 `7995d26` 为准，代码一动行号就会漂 —— 按函数名找，别按行号找。
3. **"服务端没给"是这项目的常态**，很多设计是被上游接口能力**逼**出来的。看缺陷时先分清
   "客户端写错了"和"上游只能这样"，两者的处理方式完全不同（见 `文档/04` 的分级）。
