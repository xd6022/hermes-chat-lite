# 输入框上方状态行（Claude 式）+ 每轮一个状态戳 —— 计划书 + 状态看板

- **立档**：2026-09-16 CST（Asia/Shanghai）
- **分支**：`feat/turn-status-light`（从 `origin/main` 的 `aeb8094` 开；v2.13 已合入 main）
- **起因**：用户要把交互做成"两个人交谈"的样子，并要一个**状态指示**。
  参照物是他用 Claude 时的体验 —— 图标会闪、旁边有状态词（`Ready` / `baking`），
  **一眼就知道"我是不是还得再等会儿"** ⇒ 这是个**决策信号**，不是装饰。
- **关键纠偏（走错过一回，记下来免得再绕）**：中途有一版把状态挪进对话流（轮首），代价是长轮次会滚出视口 ——
  而那恰好是最需要"要不要等"的场景。**结论：问题不在"位置"，在"内容"** ——
  输入框上方原本挂的是装饰提示词 + 重复的工具名（那确实是噪音），但那个**位置**是对的
  （位置固定才能回答"要不要等"）。最终方案 = **位置不动，内容升级**。

## 一、口径（已拍板，实现时照这张表，别再问）

### 1.1 状态行 —— **只有四个状态**（用户 2026-09-16 最终简化）

| 灯 | 状态词 | 什么时候亮 | 脉冲 |
| --- | --- | --- | --- |
| 🟢 | `空闲中` | **默认态** —— 没有在跑的任务 | 否 |
| 🟡 | `忙碌中 {secs}s` | 这一轮在跑（思考／工具／输出正文／连接暂断但服务端还在跑） | **是**（"在动"是硬要求） |
| 🟠 | `等待审批` 或 `已中断` | 等你介入（审批）／这一轮被停 | 否 |
| 🔴 | `失败（请重试）` | 出错、后端不可用 | 否 |

- **正文结束 → 回到 🟢 空闲中**（用户原话）。⇒ **不再需要"停留 ~3 秒后收起"那套逻辑**，也**不再需要"空闲时隐藏"**。
- 灯只回答"**忙／闲／败／断**"，**不看工具**（用户明确："不记录工具，不记录是否在调用工具"）。
- 计时只挂在 🟡 上（"还要等多久"只在忙碌时是个问题）。
- **没有蓝色** —— 🔵 已随"不记工具"整条撤销。
- 位置：`RunStatus.vue` 现有位置（`<RunStatus />` 在 `<ContextGauge />` 之前）—— **位置不动**。
- 形式：`{灯} {状态词}`（**灯本身就是那个表情**；头像留给轮首戳，见 1.2 —— 这是我的取舍，要改说一声）。

### 1.2 轮首戳（对话流里，永久痕迹）

- 位置：**每一轮的开头**（用户气泡之后、助手内容之前）；**每个助手轮都有**。
- 内容：`{头像} {灯}`，头像默认 `-_-`，**点用同一套四态**（不写状态词）。

| 这一轮 | 戳 |
| --- | --- |
| 跑着 | `-_- 🟡` |
| 正常结束 | `-_- 🟢` |
| 失败 | `-_- 🔴` |
| 被停 / 等审批 | `-_- 🟠` |

- **固定占一行高**（跑着时那一行就在，跑完只换颜色）⇒ **零高度变化**，不会触发 v2.6 那套贴底抖动。
- **不放重试按钮**（重试只在上面那条状态行，避免两处按钮）。
- 历史轮：重新打开老会话时一律 🟢（服务端不记录"哪一轮被中断过"）。

### 1.3 工具行 —— **本版不动**（原计划的"● 改蓝"已撤）

对话流里的工具行保持 v2.11 现状（`●/✓/✗ 名称 "参数预览" (耗时)`，灰／绿／红）。
理由：用户定了"不记录工具"⇒ 蓝色从词汇表里消失；既然不引入新颜色，就没有必要动它。

### 1.4 判据（实现照这些写）

| 输出 | 判据 |
| --- | --- |
| 🟡 `忙碌中` | 每轮开始（`resetRun()` 后 `phase='thinking'`）；包含 `thinking / tool / writing / approval→见下 / background` |
| 🟠 `等待审批` | `phase === 'approval'`（**不显示工具名** —— 审批卡片标题已经在说同一个名字） |
| 🟠 `已中断` | `phase === 'aborted'`（点了暂停／服务端取消／拿不到终态但没内容） |
| 🟢 `空闲中` | `phase === 'idle'` 或 `'done'` |
| 🔴 `失败（请重试）` | `phase === 'error'`（传输层异常或服务端 `error` 事件）；或建会话就失败（`store.bootError`） |
| 🔴 上的「重试」按钮 | **只在 `runId === null` 时给**（服务端根本没收到，重发安全）；`runId !== null` 只报错不给重试 |
| 🔴 后台但还在跑 | **绝不显示红**：`phase === 'background'`（切后台／锁屏／换网）算 🟡 忙碌中（9/13 真机纠偏过这条） |

**已知小瑕疵（第一版接受）**：刷新页面那一瞬（`store.run` 归零、重连同步还没回来 ≈1 秒）会先显示 🟢 空闲中，
再跳成 🟡 忙碌中。若要消掉这个"假空闲"，得加一个"正在同步"的中间态 —— **第一版先不加**（与"做最简单"一致）。

## 二、代价（已接受，交付说明里要写明）

1. **输入框上方从此常驻一行**（空闲时显示 `🟢 空闲中`）—— 这与最初"那块彻底不要"的想法相反，
   是用户主动要的 `Ready` 式正向信号：**"一眼知道我没在跑、可以发下一句"**。
2. 轮首戳在长轮次会滚出视口（主需求由位置固定的状态行覆盖）。
3. 换设备 / 清浏览器数据 / 超 6 小时 ⇒ 认不出在跑的那一轮（灯是实时派生量，不落盘）。
4. 重开老会话：历史轮一律 🟢（服务端不记录"哪一轮被中断过"，`end_reason` 只在会话级）。

## 三、有意开的口子（用户已知悉）

状态行的 `🟡 忙碌中` 与对话流里正在跑的那条工具行（`● mysql.query "…"`）**同时存在**。
分属两个职责：**上＝瞬时状态**（忙不忙），**下＝永久记录**（干了什么）。
v2.13 曾把工具名从状态行删掉 —— 本次不再把工具名放回来（**维持 v2.13 的删法**），口子因此收得更小。

## 四、坑位预判（实现时留神）

1. **状态行高度**：`空闲中` 与 `忙碌中 1234.5s` 长度差很多 ⇒ 固定一行高 + 文字截断，否则会顶动水位行/输入框。
2. **轮首戳零高度变化**：跑着时就把那一行画出来（只换颜色），别"跑完才插节点"。
3. **现有断言按新口径改写，别一删了之**（回归网）：`RunStatus.spec.ts` 里
   `已中断这一轮`、`等待你批准：terminal`、`正在思考`、`完成` 等断言都要改成四态新词。
4. **`data-testid="run-status"` / `:data-phase` 必须保留** —— e2e 与真浏览器探针靠它判相位。
5. **`store.run.currentTool`**：本次不再用（"不记工具"）⇒ 别顺手删字段（它在 store 里还有别的用途），
   只是状态行不再读它。

## 五、实现锚点（已勘察本机代码，只读未改；开工时照这些落点写）

### 5.1 红灯与「重试」的判据（有硬依据）

`send()`（`stores/chat.ts:1538`）只有两条"失败"路径：

| 失败路径 | 现场表现 | 灯 | 给重试吗 |
| --- | --- | --- | --- |
| ① 建会话就失败（常见：反代没注入 key → 401） | `store.bootError = '无法创建会话'`，这一轮**根本没起** | 🔴 | **给** |
| ② `POST /v1/runs` 或流的传输层异常 | `catch` 里 `store.run.phase='error'`、`errorMessage=msgOf(e)`、`ctx.transportError=true` | 🔴 | **看 `runId`** |
| ③ 服务端明确发 `error` 事件 | 走事件归约，`ctx.sawError` | 🔴 | **不给**（服务端收到了） |

```
runId === null  ⇒ 服务端根本没收到这一轮 ⇒ 给「重试」
runId !== null  ⇒ 收到了（可能已落库）⇒ 不给重试，只报错
```
依据：`store.run.runId` 只在 `POST /v1/runs` 拿回 `run_id` 后写入（`chat.ts:1070-1071`），
每轮开始由 `resetRun()` 清成 `null`（`chat.ts:1519`），恢复链从 `hcl.activeRun` 记录写回（`chat.ts:1315`）。

### 5.2 灯与计时的起点

`resetRun()` 一轮开始时：`phase='thinking'`、`startedAt=performance.now()`、`runId=null`。
⇒ 🟡 忙碌中的起点与计时起点都在这里。

### 5.3 需要"在动"的相位集合（已有常量，别另起一套）

`RunStatus.vue:37` 的 `active` computed：`thinking / tool / approval / writing / background`（+ `store.streaming`）
⇒ 本次只有 🟡 需要脉冲；`approval` 归 🟠 后不再脉冲。

## 六、本次**明确不处理**的（别顺手做）

1. **审批卡片压缩消息区**：卡片在固定区，变高会挤矮消息区。用户判断"出现概率低"⇒ **先不管**，
   也不把卡片搬进对话流（那会牵扯滚动锚定）。
2. **侧栏"某会话正在跑"小黄点**：不做。
3. **轮首戳滚出视口**：接受，不加"回到底部"浮动提示。
4. **跨设备 / 清缓存 / 超 6 小时的恢复**：不做（灯是实时派生量）。
5. **刷新那一瞬的"假空闲"**：不修（要修得加中间态，与"做最简单"冲突）。
6. **工具相关的一切**：状态行不显示工具名、不显示"是否在调用工具"、工具行不动、无蓝色。
